# Candidate path patterns

All 十神 are relative to the same original 日主. These are forms to instantiate with actual positioned participants, not claims that every chart contains every path.

Generation: 比劫 → 食傷 → 財 → 官殺 → 印 → 比劫.
Control: 比劫 → 財 → 印 → 食傷 → 官殺 → 比劫.

| Pattern | Candidate edges | Required distinction |
| --- | --- | --- |
| 官印／殺印相生 | 官殺生印，印生身 | Can 印 receive and pass support; is 財 controlling the necessary 印? |
| 食神制殺 | 食神剋七殺 | Conditions of 食神、七殺 and 日主; existence of control does not establish its adequacy. |
| 傷官合殺 | 陰日主的傷官與七殺五合 | Actual matching pair, then 合 action / 合絆 / 合化 gates. 乙日主的丙辛 is an example. |
| 食傷生財 | 食傷生財 | Actual tool, target, reception, connection to 主位 and cost of output. |
| 比劫取財／奪財 | 日主或比劫剋財 | Which participant acts on which 財; capacity, competing tools and alternative paths. |
| 干合取財候選 | A stem matches a 財 participant by 五合 | Pair, actual 合 conditions and connection to 主位; matching 財 does not mean obtaining it. |
| 財官印轉接 | 財生官殺，官殺生印，印生身 | Every link must exist and function; direct 財剋印 can coexist. |
| 財壞印 | 財剋印 | Whether this 印 is a necessary functioning tool and whether a transfer path actually changes the effect. |
| 梟奪食 | 偏印剋食神 | Both participants and the 食神's function; 偏印 alone is insufficient. |
| 傷官見官 | 傷官剋正官 | 官's role, extent of action and other routes; no event follows from the names alone. |

## 通關 candidates

| Direct relation | Alternative path to inspect |
| --- | --- |
| 官殺剋身 | 官殺 → 印 → 身 |
| 財剋印 | 財 → 官殺 → 印 |
| 比劫剋財 | 比劫 → 食傷 → 財 |
| 印剋食傷 | 印 → 比劫 → 食傷 |

For each intermediary, identify its actual position, source and participation conditions. An absent intermediary invalidates that concrete candidate; an unknown or impaired link leaves effectiveness unresolved. Neither result deletes other existing relations.

正偏 identity stays fixed after 制化. Calling a controlled 七殺 `偏官` describes its use, not a new 五行 or 陰陽 classification. Likewise, `假官當財／過河財` remains a conditional semantic proposal under [mangpai-support](../../mangpai-support/SKILL.md), not an automatic reclassification.
